# Weekly plan (Monday morning, unattended)

Goal: decide the reels of the coming week in advance, so the owner can generate the missing characters, objects and illustrations in Gemini (free) before the nightly factory needs them.

1. Read `FACTORY.md` (sections 1, 1b, 2), `schedule.json`, `growth/calendar.json`, `growth/topics.md`, `growth/insights.md`, `growth/experiments.json`, `log/published.json` and `factory/library/index.json`.
2. **Publishing days:** from the rules in `schedule.json` and the log, list the dates in the next 7 days (today included) on which the factory will publish.
3. **One topic per day.** Follow FACTORY step 2 exactly: special dates first, category rotation, demand check, a format from FORMATS.md, and no repeats of past topics. Do a quick plausibility check that each topic has at least two solid sources (full verification happens on the day).
3b. **Experiment for each video.** Read `batch` and `protocol` in `growth/experiments.json`. The rule is ONE primary variable per batch of 3 videos; everything else stays at its `control`.
   - While the batch is `running` and has free slots (`slots` minus `videos`), give the next publishing days the variant: add `"experiment": {"batch", "test", "option", "role": "variant"}` to their entry and append the date to `batch.videos`.
   - Special-date (themed) reels and any day beyond the batch get `"role": "base"` (tests nothing, still counts for the baseline). If the batch is closed and `queue` has a next test, open it first: move the finished batch to `history`, set the new `batch` (new id, hypothesis in one sentence, control and variant from the queue entry), set the tested key to `testing` and the previous one back to `fixed`.
   - Never assign two variables to the same video. Do not change `fixed` tests.
   - Write the hypothesis and how it will be measured (primary metric `watch_pct`, 7-day figures, success rule in `protocol`) in `batch.hypothesis`, so the review and the owner can read it.
4. **Characters, objects and illustrations:** for each reel, list EVERYTHING it needs to show the story well: characters (people, animals), objects (props, tools, food, vehicles, instruments...) and illustrations (scenes, landscapes, diagrams, places, key visuals). Do not limit the list to characters. Match each item against the library (by name or tags). An item that is not there is `missing`. Anything that can be reasonably drawn in code as a simple shape (a plain circle, arrow or chart) does not need a sheet; anything that must look recognisable and in the cat's style does.
5. **Prompts:** for every missing item, write the Gemini prompts to `growth/week_prompts.md`, following `factory/library/PROMPT.md` and the copy-paste format below. Characters: two sheets (movement, acting), with the right cycle (walk cycle for people, run cycle for four-legged animals, flying or swimming for others). Objects and illustrations: one sheet of 9 cells (see "Object / illustration sheet" in PROMPT.md); group several small items of the same reel on one sheet when possible, to keep the owner's work low.
6. Write `growth/week_plan.json` as `[{"date", "topic", "category", "format", "event"?, "characters": [...], "objects": [...], "illustrations": [...], "missing": [...], "experiment"?: {"batch", "test", "option", "role"}}]`, then commit and push. Edit only `growth/`.
7. **Notification in Spanish, at most 7 lines:** the week's dates and topics in one line each, then one line "Experimento: <variable>, <opción> en <fechas> (se mide con retención a 7 días)" (or "Sin experimento esta semana"), then "Falta por generar: X, Y" listing characters, objects and illustrations (or "No falta nada"), then "Los prompts están en growth/week_prompts.md o pídemelos en el chat." Never generate images yourself and never spend ElevenLabs credits.

Copy-paste format for `week_prompts.md`: one block per sheet, starting with which images to attach (`STYLE_REF.png`, plus the character's movement sheet when it is an acting sheet), then the full prompt text.
